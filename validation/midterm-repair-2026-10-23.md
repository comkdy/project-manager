# 중간 검토 후 안정화 결과

2026-10-23 · 기존 기능 수정 및 연계 검증. 기능 추가 제안은 이번 작업에서 제외했다.

## 수정 결과

| 우선순위 | 발견한 문제 | 반영한 수정 |
|---|---|---|
| P1 | AI 분석의 날짜·재측정 조건이 사용자 근거와 달라도 통과 | 사용자 원문의 날짜·시각·시간대를 실제 추출값과 비교한다. 재측정 정책의 반대·부정 표현과 잘라낸 인용을 검사한다. 확정할 수 없는 조건은 기존 기준 확인 흐름으로 보낸다. |
| P2 | UUID·시간형 값에서 카드 JSON 응답 실패 | 조회값 정규화에서 UUID, time, timedelta를 처리하여 표·차트 캐시·Python 입력이 같은 변환을 사용한다. |
| P2 | 느린 DB 등록·활성화·테이블 검사가 일반 조회까지 대기시킴 | 설정 쓰기 잠금과 활성 연결 조회 잠금을 분리했다. 메타데이터 커밋 후 연결을 반환하고 메모리 상태를 교체하여 잠금 순환 대기를 피하며, 늦은 게시가 최신 revision을 되돌리지 않게 했다. |
| P2 | 자동 갱신한 차트의 실제 버전과 표시 버전 불일치 | 일반·Python·간트 카드에서 계산 응답의 실제 버전을 표시한다. 보드 배치나 카드 편집 입력은 자동 교체하지 않는다. |
| P2 | 프로젝트 질문함에서 여러 원천을 참조하는 분석 질문 누락 | 전체 원천 가시성 검사를 먼저 수행하고 질문의 프로젝트 필터를 별도로 적용한다. 숨긴 원천을 참조하는 질문은 계속 차단한다. |
| P2 | 다른 관리자의 저장으로 미저장 지식 초안 소실 | 편집기를 초안 ID로 유지하고 편집 시작 revision과 입력을 보존한다. 외부 변경이나 처리 완료를 알리고, 최신 초안을 명시적으로 다시 불러오기 전 저장·승인을 막는다. |
| P2 | 분석 이력 조회가 큰 결과와 동일 정보를 반복 조회 | 목록 조회 SQL에서 결과 JSON 컬럼을 제외했다. 관련 원천·질문·승인 지식을 요청당 묶어 조회한다. 상세 조회의 결과는 그대로 유지한다. |
| P2 | 연결 상태 조회 실패 후에도 이전 ‘연결됨’ 표시 | 조회 실패를 우선 표시하고 마지막 성공 확인 시각을 보여준다. 정상 조회가 돌아오면 연결 상태도 복구된다. |
| P2 | 전체 카탈로그 크기 제한이 분석 채팅까지 차단 | 요청 분류 후 SQL·데이터셋·카드 경로에만 전체 카탈로그를 준비한다. 분석은 기존 분석 전용 카탈로그를 사용한다. |
| P2 | 두 사용자의 첫 접속에서 대시보드 생성 충돌 | 중복 생성은 기존 보드를 유지하고 두 요청 모두 저장된 동일 보드를 읽는다. |
| P2 | 원천 자동 탐색과 수동 데이터셋 저장의 버전 충돌 | 같은 데이터셋에 동일한 PostgreSQL 트랜잭션 잠금을 사용하고 잠금 획득 후 최신 버전을 확인한다. 사용자 작성 SQL과 과거 버전을 보존한다. |
| P3 | DB·계정 전환 후 이전 분석 ID 재사용 | 선택값을 초기화하고 DB·사용자 범위가 일치할 때만 분석 ID를 전달한다. |

추가로 마이그레이션 검사를 현재 5단계와 일치시켰다. 단순 기대값 수정에 그치지 않고 반복 실행 후 승인 지식·초안·매핑·질문·답변·감사·원천 기록의 보존을 확인한다. README의 카드 버전 정책과 현재 차트 지원 안내도 실제 동작에 맞췄다.

## 검증

- 전체 백엔드 회귀 검사: **938개 통과**, 실패·건너뜀 없음, 474.44초. `backend/tests` 전체와 `demo/test_generator.py`를 임시 PostgreSQL에서 실행했고, 완료 후 임시 DB를 제거했다.
- 프런트엔드: 106개 통과, 실패·건너뜀 없음. TypeScript 검사 및 배포용 Vite 빌드 성공.
- DB 동시성 집중 검사: 느린 등록·활성화·표시 설정 중 기존 연결 조회, 동시 첫 보드 생성, 자동 탐색과 수동 버전 저장 충돌을 실제 임시 PostgreSQL에서 검증했다.
- 분석 조건: 다른 연도·시각·시간대, 한국어/영문 표현, 정책 부정·모호성·잘라낸 인용을 검증했다. 채팅 분류부터 SQL·데이터셋·카드의 응답 흐름은 모의 모델 응답으로 검사했다.
- 전체 검사 이후 분석·채팅 관련 **147개 추가 재검증 통과**(기존 125개 + 신규 경계 사례 22개). `not want to use`, `avoid/skip/exclude/omit`, `빼고/배제` 등 부정 표현과 정상적인 NULL 보존 요청을 구분한다. 또한 현재 해석하지 않는 `오전/오후`, `AM/PM`, `at 3pm`을 날짜의 자정이나 오전 시각으로 축약하지 않고 확인 절차로 보낸다. 이 추가 검사는 전체 938개와 중복되는 항목이 있으므로 단순 합산하지 않는다.
- 효율성: 분석 목록에서 결과 컬럼을 읽지 않는지와 다수 이력의 질문·원천 조회를 공유하는지 검사했다. 전체 부하 시험이나 운영 성능 수치를 측정한 것은 아니다.
- 실제 화면: 수정 앱을 재시작하고 전체 대시보드 6개 카드·간트, XXXA 데이터 6행, 분석 카탈로그 17개 계열·이력 20건, 저장된 split 결과 17개 계열, 결과에서 AI 지식 질문함 이동을 확인했다. 해당 탐색 중 브라우저 오류·경고는 없었다.

## 데이터 보존과 검증 범위

전체 백엔드 검사는 임시 관리 DB를 새로 만들고 읽기 전용 데모 원천에 연결하여 수행한다. 실제 앱의 DB 연결 설정·카드·지식·분석 결과는 검사용으로 바꾸지 않았다. 앱 화면 조회 과정의 정상 카탈로그 동기화는 허용했다. 수정 전 소스 백업은 `.local/midterm-repair-baseline-2026-10-23.zip`에 있다.

외부 LLM의 실제 판단 품질과 실제 회사 SSO 연결은 이번 검증에 포함하지 않았다. 해석하기 어려운 날짜·정책 표현은 추정하여 실행하지 않고 기존 확인 절차로 보낸다. Plotly 번들의 기존 크기 경고와 Starlette/httpx의 기존 폐기 예정 경고는 남아 있으며, 빌드·검사 실패는 아니다. 새 기능, SSO 어댑터 구현, 장시간 운영 부하 검증은 별도 작업이다.

앱에는 수정된 백엔드와 프런트엔드 빌드를 반영했으며 `http://127.0.0.1:8000`에서 실행 중이다.
