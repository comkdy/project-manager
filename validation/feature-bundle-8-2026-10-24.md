# 운영 점검·문제 안내·기존 화면 연결 검증

작업일: 2026-10-24 (Asia/Seoul). 백업·복구 검증 다음 작업으로 관리자 운영 점검을 구현하고 현재 앱 `http://127.0.0.1:8000`에 반영했다.

## 구현

- 작업 상태에 **운영 상태 점검**을 추가했다. 관리 DB, 원천 읽기 전용 연결, 분석 대기·실행, 질문·승인, 수집 설정, 정기 예약, 처리기 3종, 본인 AI 연결 준비, 백업 기록, 외부 보관을 구분한다.
- 확인 필요·미확인 항목을 먼저 표시하고 전체 항목을 펼칠 수 있다. 점검 시각·범위·관측 시각과 안내를 제공한다. 60초 지난 결과는 이전 결과로 안내한다.
- DB 설정 탭, 내 AI 설정, 질문함, 전체 작업, 정기 분석, 백업·복구 준비로 이동한다. 전체 목록 바로가기는 프로젝트 및 작업 상태 필터를 초기화하고 해당 위치로 스크롤·키보드 초점을 이동한다.
- 자동 작업 관측은 메모리에만 저장하고 기존 작업의 반환값·예외·취소·재시도 로직을 유지한다. 오래된 실행의 완료가 재시작 이후 관측값을 덮어쓰지 못한다.
- 관리자 권한을 실제 저장 상태로 검사한다. 점검은 기록 조회와 원천 읽기 전용 연결 확인만 수행하며 AI 호출·작업 시작·승인·예약 수정·백업 생성을 하지 않는다. 분석 결과 본문을 로드하지 않는다.
- Pydantic 계약에서 소비 타입을 생성하고 기존 계약 검사에 포함했다. 관리 DB 스키마와 기존 데이터는 변경하지 않았다.

사용법과 해석: [OPERATIONS_CHECKS.md](../OPERATIONS_CHECKS.md). API: [CONTRACT.md](../CONTRACT.md).

위 검사 건수는 중복되므로 합산하지 않는다. 전체 검사 후 과거 분석·실패 답변을 포함한다는 안내 문구만 보완하고 운영 검사를 다시 통과했다. 기존 테스트 클라이언트 사용 중단 예정 경고와 Plotly 번들 크기 경고는 남아 있다.

운영 검사에는 관리자/편집자/조회자·권한 회수, 원천 범위 분리, 대기/실행 기한·예약 지연, 일시정지와 다른 DB 예약, 본인 키만 확인, 비밀 값 비노출, 연결 실패 시 백업 안내 유지, 처리기 오류·만료·재시작, 백업 기록 읽기 실패·작업 중·오래된 생성 시각·미래 시각·재검증 구분을 포함했다. SQL 관측으로 운영 점검 중 INSERT/UPDATE/DELETE 및 분석 결과 본문 로딩이 없음을 검사했다.

## 실제 연계 및 브라우저

임시 관리 DB와 읽기 전용 `wafer_fab_demo`를 사용했다. AI 응답은 고정 검증 어댑터이므로 외부 AI 서버 연결이나 응답 품질을 검증한 결과는 아니다.

실제 HTTP API 및 처리기에서 다음을 확인했다.

1. 정기 분석 실행 중 취소 → 결과 폐기 → 원래 조건·기간·일정·비교 대상이 유지된 재시도 완료.
2. 원래 분석·취소·재시도 이력과 질문·승인 기록 보존.
3. 실제 질문의 답변 초안 승인 → 승인 버전과 확인한 조건으로 **37,251행 재분석** → 기존 일정 조건 교체.
4. 과거 비교 근거 보존, 프로젝트의 이동 기간에 따른 측정 계열 누락 알림, 정확한 이전 결과 비교, 알림 확인 후 근거 유지.
5. 운영 점검 전후 기존 분석·질문·승인·일정·이력·비교·알림·대시보드·프로젝트/데이터셋 응답 동일.
6. 위 기록을 포함한 **30개 테이블·64행** 백업 및 실제 임시 복원, 재검증, 생성 요청 재전송 시 중복 없음.
7. 백업 전후 운영 점검에 검증 완료 기록 반영, 외부 보관은 계속 미확인, 원천 연결 및 처리기 관측 확인.

결과: [feature-bundle-8-qa.json](feature-bundle-8-qa.json).

브라우저에서 최초 진입 시 운영 점검이 자동으로 실행되지 않는 것, 60초 경과 후 안내와 수동 갱신, DB 설정의 올바른 탭·본인 AI 설정·질문함 이동을 확인했다. 프로젝트를 선택한 뒤 백업 바로가기로 전체 프로젝트로 전환되고 기존 공통/프로젝트 일정이 모두 보이는 것을 확인했다. 작업·일정·복구 바로가기의 스크롤과 초점도 확인했다. 질문함에 승인 완료 기록이 유지되고, 백업 이후 기존 알림의 정확한 결과 비교 표가 열렸다. 검증 및 실제 앱 브라우저 오류·경고 로그는 0건이었다.

검증 종료 후 임시 앱·임시 관리 DB·검증 전용 백업 폴더만 정리했다. 실제 앱과 백업은 유지했다.

## 현재 앱 보존 및 백업 재검증

- 프로젝트 **3개**, 공통 데이터셋 **13개**, 공통 카드 **6개** 및 프로젝트별 정의가 그대로 유지됐다.
- 정의 해시: `108bdd300ecee628ec3e3f4bf218c8b06a9fa9f60868e56bf274aa2c6b6edba5`.
- 운영 점검에서 기존 백업 화면으로 이동해 저장 백업 `c3ec1607b7e5475aa4195cb3bf805930`을 실제로 재검증했다. 생성 시각은 02:13:34를 유지하고 검증 시각만 02:36:36으로 갱신됐다.

## 확인 범위의 한계

운영 점검은 수동 요청 시점의 상태이며 상시 감시·자동 복구가 아니다. 처리기 관측은 현재 응답 서버만 대상이고 개별 작업 성공을 대신하지 않는다. 실패·기준 확인 상태의 과거 기록도 집계한다. AI 연결은 저장된 준비 상태만 확인하며 외부 호출을 수행하지 않는다. 백업 진단은 기록 기준이고 파일·현재 키 검사는 기존 재검증이 담당한다. 암호화 키와 백업의 외부 보관은 별도 준비가 필요하며 운영 DB 덮어쓰기 복구는 이번 작업에 포함되지 않는다.
