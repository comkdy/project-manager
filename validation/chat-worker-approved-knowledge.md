# ML 결과 승인 → AI 챗 지식 활용 실제 검증

2026-10-25. 사용자의 명시적 요청에 따라 앞 단계의 실제 모델 ML 결과 한 건을 검토·승인하고, 현재 OpenRouter 모델 `z-ai/glm-5.3-flash`가 새 승인 지식을 인용하는지 실제 앱에서 확인했다. 원시 측정 행은 외부에 보내지 않았다. 이번 단계에서는 앱 코드를 변경하지 않았다.

## 검토와 승인

- 원본 분석: `4591b8bf-fb52-45a0-8626-0e1fd4bd176f`.
- 확인 요청: `af58a484-72de-4b6a-876a-e07a175d0c53` → **answered**.
- 검토 초안: `32aafb13-397d-4fa4-af6c-92e787d98cad` → **approved**.
- 새 승인 지식: `06c319ee-2bb4-40b2-9d79-c76da7cc6fb2`, **버전 1**.
- 이름: 현재 데이터 분석: XXXA oper B Recipe별 Inline MAIN·EPM PARA3 wafer 단위 결합 · 4591b8bf.
- 범위: XXXA, 결합 데이터셋 `aa3f3390-57a2-41b9-a185-a045dd3757c3` v2.

승인 전 초안의 분석 요약이 원본 실행의 계산 요약과 정확히 같고, 데이터셋·버전·필터·시각·ML 설정이 일치하는지 확인했다. 243행 중 학습 183행, 검증 49행, Lot 중복 제외 11행이며, 학습 마지막 시각이 검증 시작보다 앞선다. 승인 검사 항목 `issues`는 빈 목록이었다.

합성 DB의 관측·예측 결과로 승인했다. 통계적 유의성이나 인과 효과를 확정하지 않으며 실제 사내 공정 효과로 일반화하지 않는다는 검토 메모를 남겼다. 이전 모델 미호출 결과와 다른 검토 대기 항목은 승인하지 않았다.

## 실제 AI 챗 질문과 답변

질문: “XXXA의 oper B Recipe와 Inline MAIN 중 EPM PARA3 예측에 중요하게 볼 항목은 무엇이고, 다음에는 무엇을 확인하면 좋을까? 승인된 ML 분석 결과와 평가 사례를 근거로 설명해줘. 새로 계산하지 말고, 근거의 조회 시점과 한계도 알려줘. 인과관계는 단정하지 마.”

실제 모델은 `evaluation_cases` 경로로 승인 지식을 조회했다. 새 계산을 생성하지 않았고, 자연어 설명 상태는 **ready**다. 다음 내용이 설명에 포함됐다.

- 이 검증 모델에서는 Inline MAIN의 예측 기여가 Recipe보다 컸다. 값을 섞었을 때 예측 오차 증가와 Pearson 상관 0.982314를 근거로 설명했다.
- ML 평균 절대 오차 0.00546758, 중앙값 기준 0.0417122, R² 0.976275를 승인된 기록에서 인용했다.
- Lot별 변동·그룹 표본 수·다른 기간의 재현 여부를 다음 확인 대상으로 제안했다.
- 변수 중요도를 인과 효과 비율로 해석하지 않았으며, 조회 시점·데이터셋 v2·합성 데이터의 한계를 명시했다.

근거 카드에 새 지식이 포함된 것만 확인한 것이 아니다. **답변 문단의 `analysis_result` 인용이 새 지식 ID와 버전 1을 직접 참조**하고, 그 지식의 실행 근거가 위 원본 ML 실행 ID를 가리키는 것을 검사했다.

대화: `c95c2f95-6824-41ff-929e-db75c5163140`. 저장 후 다시 읽어도 검증된 설명과 인용이 동일했다. 실제 화면에서 이 대화를 열어 결과를 확인했다.

## 외부 전송과 범위·보존 검사

모델 설명 입력은 승인 사례/계산 요약, 데이터셋 식별·버전, 질문과 적용 범위로 한정된다. 외부 전송 전 설명 입력의 중첩 구조에 측정 행·샘플 행·데이터 미리보기·조회 결과가 없음을 확인했고, 실행 근거도 `summary`만 제공하는 기존 경로를 사용했다. 원천 조회나 ML 재계산을 하지 않았다.

새 지식은 XXXA에서 검색되고 XXXB/XXXC에서는 검색되지 않음을 확인했다.

승인 직전 메타데이터 32개 테이블 **1,706행**의 개별 행 해시와 비교했다. 기존 행 중 바뀐 것은 요청한 확인 요청과 초안의 승인 상태 두 행뿐이다. 추가된 것은 승인 지식/버전 각 1개, 승인 감사 기록 1개, 검증 대화/턴 각 1개다. 기존 분석 결과·데이터셋·대시보드·다른 승인 지식은 그대로다.
