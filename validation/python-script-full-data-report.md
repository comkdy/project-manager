# Python 카드 전체 데이터 검증

검증일: 2026-10-22 (Asia/Seoul)

## 적용 내용

- 입력 10,000행 및 입력 JSON 8MiB 제한 제거. 데이터셋의 기간·필터 결과 전체를 df로 전달.
- 서버 커서로 2,048행씩 읽어 실행별 임시 파일에 기록. API에서 전체 행 목록/JSON을 만들지 않음.
- 자동 행 번호 및 전체 정렬 제거. 데이터셋 SQL과 사용자 스크립트에 지정한 정렬은 유지.
- 격리 프로세스에서 전체 DataFrame 구성. 원래 컬럼명과 NULL 보존, 반복 문자열 메모리 재사용.
- 차트 응답/캐시에는 Figure와 메타데이터만 저장. 원본 행은 브라우저에 다시 전송하지 않음.
- 동일 요청 캐시·동시 요청 병합 유지. 조회 시작 전 실행 슬롯 확보, 성공/실패 시 자원 정리.

## 실제 EPM 카드

전체 프로젝트의 `EPM PARA1 측정값 분포`를 저장 없이 실행했다.

| 범위 | df 입력 | NULL 측정값 | 히스토그램 합계 | DB 집계 일치 |
|---|---:|---:|---:|---|
| 공통 기간: 2026 WW40부터 | 14,907 | 31 | 14,876 | 일치 |
| 공통 기간 해제 | 37,251 | 70 | 37,181 | 일치 |

NULL도 df에 들어 있으며, 표시된 히스토그램 코드의 notna 조건으로 제외된다.
XXXA 프로젝트의 기존 6개 카드 결과도 기존 SQL 집계/조회 결과와 일치했다.
평균을 합계로 바꾸는 스크립트 수정도 반영됐으며 저장된 카드·데이터셋은 변경하지 않았다.

## 대용량 처리 측정

`python_script_load_test.py` 사용. 원천 테이블을 만들거나 변경하지 않고 PostgreSQL
generate_series로 9개 컬럼의 합성 측정 데이터를 생성했다. 실제 읽기 전용 서버 커서,
임시 파일 전달, 격리 실행, 응답 캐시 경로를 사용했다. 아래 시간은 이 처리 경로의
동시 요청 측정이며 HTTP 인증·전송 및 브라우저 렌더링 시간은 포함하지 않는다.

| 입력 | 동시 호출 | 조회·worker 실행 | 전체 시간 | worker 최고 메모리 | 응답 크기 |
|---|---:|---:|---:|---:|---:|
| 100,000행 | 5 | 1회 | 1.77초 | 105.76MiB | 2,118B |
| 1,000,000행 | 30 | 1회 | 6.64초 | 228.84MiB | 2,153B |

100만 행 전달 파일은 64.64MiB였다. 모든 행이 히스토그램 합계에 포함됐다.
전달 측정 프로세스의 최고 메모리는 10만 행에서 99.43MiB, 100만 행에서 100.82MiB였다.
합성 데이터의 반복 문자열 비율, 컬럼 수와 실제 SQL에 따라 시간·메모리는 달라진다.

## 회귀 검증과 보호 장치

- 실제 API에서 5명/30명 Python 카드 요청이 각 갱신 주기당 1회만 실행됨을 검증.
- 10,000행·8MiB 초과, 마지막 행 포함, NULL 배치 경계, 원래 컬럼명, 읽기 전용 커서 검증.
- 조회 실패·디스크 부족·시간 초과·메모리 오류 뒤 정리 및 다음 실행 복구 검증.
- 기존 차트 생성, AI 제안/재실행, 필터·기간, import 금지와 카드 격리 회귀 검증 통과.
- 프런트 카드 편집 테스트, 타입 검사 및 프로덕션 빌드 통과.

행 수로 자르지 않는다. 자원 보호를 위해 동시 조회·실행 2개, worker 1GiB/60초,
입력 전달 120초, 대기 15초, 브라우저 표시 결과 4MiB/64 trace 제한은 유지한다.
원천 DB statement timeout도 유지하며, 실패 시 일부 데이터로 계산한 결과를 반환하지 않는다.
