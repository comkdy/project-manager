# 승인 근거를 해석하는 AI 챗 — 구현·검증 기록

검증일: 2026-10-25. 실행 중인 앱: http://127.0.0.1:8000/.

## 구현한 사용 흐름

AI 챗이 현재 프로젝트·데이터셋과 관련된 승인 사례를 찾은 다음, 승인된 계산 결과와 관측을 바탕으로 중요한 항목, 다음 확인 사항, 해석 한계를 자연어로 설명한다. 변수 중요도가 있으면 해당 모델에서 비교한 항목들의 예측 기여를 설명하며, 인과 효과로 표현하지 않도록 지침과 검증을 적용했다.

각 문단의 **이 설명의 근거 확인**을 펼치면 승인된 원문과 사례 버전을 확인할 수 있다. 원문은 모델이 다시 쓰지 않고 서버가 연결한다. 계산 결과의 **근거 분석 열기**에서는 원본 실행으로 이동하며, 기존 **연결된 질문·검토 열기**에서 승인 내역을 확인하고 다시 채팅으로 돌아올 수 있다.

기존 사례 카드와 추가 분석·데이터셋·카드 요청 버튼은 **근거 사례 · 조건 확인 및 추가 분석** 안에 유지했다. 설명 요청만으로 데이터 재계산, 데이터셋·카드 저장, 새 지식 승인 등을 수행하지 않는다.

## 근거와 대화 보존

- 모델에 원천 행이나 SQL 카탈로그를 넘기지 않는다. 승인된 사례·계산 요약과 적용 범위를 사용한다.
- 근거 ID, 본문의 숫자, 대표적인 인과 단정·경향 과장 표현을 확인한다. 근거 인용문은 서버가 원본에서 그대로 연결한다.
- 모델 응답을 받은 뒤 승인 상태와 근거를 다시 조회한다. 생성 도중 근거가 바뀌면 해당 설명을 사용하지 않는다.
- 저장한 대화도 현재 승인 상태·버전·적용 범위·근거 내용이 유지되는지 확인한 뒤 설명을 복원한다. 철회되거나 변경된 근거를 이전 설명이나 후속 모델 대화에 재사용하지 않는다.
- 설명 생성이 실패해도 현재 사용 가능한 승인 사례와 기존 제안 버튼은 유지하며, 실패 안내도 대화에 보존한다.
- 이 검증이 모든 자연어 문장의 의미적 정확성을 증명하는 것은 아니다. 설명은 승인 자료에 대한 AI 해석이며 새 승인 사실이나 인과 판정이 아니다.

## 실제 모델·화면 검증

현재 연결된 합성 DB의 XXXA 사례와 승인된 ML 결과를 사용했다. 이번 작업에서 원천 데이터나 승인 결과를 바꾸지 않았다.

| 항목 | 확인 결과 |
|---|---|
| 참고 사례 | `ceb1f7d8-1f3c-4bb7-96dd-7bd9bf46e230` v1 |
| 승인된 분석 지식 | `b7439730-d434-4f34-9480-63b7601ad4a9` v1 |
| 데이터셋 | `aa3f3390-57a2-41b9-a185-a045dd3757c3` v2 |
| 원본 분석 | `242797fb-7de0-4641-a92f-ad78c3339a28` |
| 연결된 확인 요청 | `8c5c1094-8bcd-489c-b787-eeb1360aea29` — 반영 완료 |
| 최종 저장 대화 | `bf8c5353-8349-4de1-b562-3ade7b0773c0` |

실제 모델은 Inline MAIN이 Recipe 구분보다 해당 모델의 EPM PARA3 예측에 더 크게 기여했다고 설명했다. Recipe별 Lot 구성·측정 시점 분포를 확인하고 이후 데이터에서 관계가 재현되는지 검증하도록 제안했으며, 합성 데이터라는 점과 인과관계를 확정할 수 없다는 한계를 함께 표시했다.

실제 앱의 `/api/chat` 응답은 `evaluation_cases` 및 `narrative.status=ready`로 완료됐다. 대화를 저장한 뒤 다시 조회한 자연어 설명과 인용이 최초 응답과 동일한 것을 확인했다. 브라우저에서도 해당 저장 대화를 열고 **문단 근거 → 원본 ML 결과 → 연결된 확인 요청의 반영 완료 내역 → 채팅 복귀**를 확인했다.

화면: [자연어 설명과 다음 확인 사항](../.local/narrative-chat.png).
실제 응답 기록: `narrative-chat-live.json`, `narrative-chat-saved.json`.

실제 검증에서 찾은 문제도 수정했다. 처음에는 모델이 내부 추론에 응답 한도를 모두 사용했고, 이후 모델이 인용 원문을 재작성하면서 검증에 실패했다. 설명 단계의 응답 예산을 조정하고 근거 ID를 선택하면 앱이 원문을 연결하도록 변경했다. Recipe별 평균 차이를 일관된 경향으로 확대하는 표현을 제한했고, “인과관계가 확정된 것은 아닙니다” 같은 한국어 부정 표현이 잘못 차단되지 않도록 보정했다.

최종 보정 후 재검증 명령:

```powershell
.venv/Scripts/python.exe -m pytest backend/tests/test_evaluation_narrative.py backend/tests/test_evaluation_chat.py backend/tests/test_evaluation_chat_workflow.py backend/tests/test_chat_history.py -q
.venv/Scripts/python.exe -X utf8 validation/verify_narrative_live.py --save-history
.venv/Scripts/python.exe -X utf8 validation/verify_narrative_preservation.py
```

전체 연결 범위와 재현 명령은 [REGRESSION.md](../REGRESSION.md)에 있다. 기존 Starlette/httpx 사용 중단 예고와 큰 Plotly 배포 파일 경고는 실패가 아니며 이번 변경의 오류는 없었다.

데이터 대조는 변경 전 기록 `narrative-chat-metadata-before.json`을 기준으로 원래 행들의 내용 해시를 비교했다. 테스트·조회 과정에서 감사 기록 23행, 지식 조회 문맥 87행, 검증 대화 3개·질문 4개가 추가됐다. 기존 프로젝트·데이터셋·카드·지식·질문·승인·분석 기록은 변경되지 않았다. 대조 결과는 `narrative-chat-preservation.json`에 보존했다.

앱을 새 코드와 빌드로 재시작했고, 최종 저장 대화를 열어 둔 상태다.
