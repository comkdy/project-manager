# 정기 분석 실행 이력·결과 비교·알림 근거 검증

작업일: 2026-10-24 (Asia/Seoul). 정기 분석·변화 알림 다음 묶음으로 실행 이력과 저장 결과 비교를 구현하고 현재 앱 `http://127.0.0.1:8000`에 반영했다.

## 구현

- 작업 상태의 일정별 **실행 이력·결과 비교**: 예약 실행·현재 조건의 원래 분석·취소·재시도 연결, 완료 시각·소요 시간·질문 수, 기존 결과/질문/작업 제어로 이동.
- 변화 알림의 **변화 근거 비교**: 이전/선택 결과의 PARA별 평균·유효 표본·평균 차이·판정 기준. 상태/방향 변화, 계열 추가/누락, 단순 수치 변동을 구분하고 달라진 항목/전체 항목 필터 제공.
- 실행·일정·알림에 실제 비교 대상을 저장한다. 승인 후 조건 교체, 다음 실행, 알림 확인 완료가 과거 근거를 바꾸지 않는다. 재시도는 원래 기간·일정·비교 연결을 보존한다.
- 조건·기간 길이/간격·원천·방법·승인 근거가 다른 결과, 미완료 결과, 비교 대상 미기록은 비교 제한 이유를 표시한다. 기존 원천 공개 및 프로젝트 범위 검사를 재사용한다.
- 새 PARA 기준 확인이 필요한 완료 결과는 기존 scheduler와 동일하게 변화 알림 항목으로 세지 않는다. 통계는 수치 비교만 제공한다.
- 이력 20건/쪽, 비교 100계열/쪽. 이력 조회는 결과 본문을 읽지 않고 시각+ID 커서를 사용한다. 복합 인덱스를 추가했다. 읽기 동작은 원천 조회·예약 변경·알림 확인을 수행하지 않는다.
- canonical Pydantic 계약과 생성 브라우저 타입, 기존 버전 보존 마이그레이션을 추가했다.
- Windows PowerShell에서 정상 서버를 시작 실패로 표시하던 문제 수정: 건강 상태 조회를 `-UseBasicParsing`으로 수행하여 대화형 확인 요청을 없앴다. 기존 방식의 `NonInteractive` 실패와 수정 후 HTTP 200, 실제 두 차례 재시작 성공으로 확인했다.

사용법은 `SCHEDULED_ANALYSIS.md`, 계약은 `backend/app/analytics/history_contract.py`와 `CONTRACT.md`에 기록했다.

## 실제 앱 경로·브라우저

임시 PostgreSQL 메타데이터와 읽기 전용 `wafer_fab_demo` 원천으로 `:8001` 검증 앱을 실행했다. 외부 AI 대신 기존 검증용 고정 응답 어댑터를 사용했다.

`validation/verify_feature_bundle_6_qa.py`는 실제 HTTP API와 worker/scheduler로 다음을 확인했다.

1. 완료 분석 → 정기 일정 → 자동 실행 → 실행 중 취소 → 취소 결과 미저장 → 기존 재시도로 완료.
2. 이력에 원래 분석·취소 실행·재시도 결과가 남으며 재시도 기간과 비교 대상이 유지됨.
3. 기존 질문의 실제 답변 초안 승인 → 승인 근거와 명시한 수치 기준으로 37,251행 재분석 → 기존 일정 조건 교체·재개.
4. 승인 상태 보존, 조건 교체 후에도 이전 재시도의 비교 대상·행 근거 동일.
5. 실제 프로젝트의 최근 4일 조건을 정기 실행하여 조회 범위에 측정 계열이 없어진 경우 변화 알림 생성. 프로젝트 lot 범위·승인 참조 유지, 알림과 비교 화면의 이전 결과 ID 일치.
6. 프로젝트 필터 격리, 알림 확인 후 근거 보존, 공통 카드 2개 유지.

결과는 `validation/feature-bundle-6-qa.json`에 저장했다. 검증 종료 후 임시 앱과 그 프로세스가 생성한 임시 메타데이터 DB를 제거했다.

실제 브라우저에서는 공통 일정 이력 → 이전 비교 → 전체 항목 필터 → 실행 조건 펼치기 → 재시도 원본 분석 열기, 확인 완료된 프로젝트 변화 알림 → 계열 누락 근거 비교, 프로젝트 필터를 확인했다. 브라우저 경고·오류 로그 없음.

## 범위

업그레이드 전 기록의 비교 대상을 임의로 복원하지 않는다. 새 일정/조건 교체 또는 이후 완료 실행부터 정확한 연결을 기록한다. 비교는 저장된 기술 통계이며 원천 재조회나 통계적 유의성·인과관계 판정을 하지 않는다. 서버 실행 및 활성 DB 조건, 앱 내부 알림, 명시적인 수치 기준 입력은 기존과 같다. 외부 AI 실서비스 품질과 사내 SSO 연결은 이번 검증 범위에 포함하지 않았다.
