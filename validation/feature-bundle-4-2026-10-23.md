# 작업 재시도·취소 구현 및 검증 — 2026-10-23

## 반영 범위

- 통합 작업 상태와 분석 상세에 서버 권한에 따른 재시도·취소 버튼, 확인 창, 상태 변경 방어, 연결된 재시도/원래 작업 이동을 추가했습니다.
- 대기 분석은 즉시 취소, 실행 중 분석은 `취소 요청됨 → 취소 완료`로 처리합니다. 행 잠금과 실행 중 확인으로 취소 뒤 도착한 계산 결과·오류·새 질문이 취소 기록을 덮어쓰지 못하게 했습니다.
- 실패·취소 완료 분석은 같은 조건의 새 실행으로 연결됩니다. 원본 요청·결과·질문을 보존하며 같은 부모에 대한 중복 재시도는 기존 자식을 반환합니다. 원천·프로젝트 범위·승인 근거·실행 한도를 다시 검사합니다.
- 미확정 AI 조건안 취소와 관리자 지식 수집의 취소·재시도를 연결했습니다. 수집의 실행 상태 버전은 설정 버전과 분리하고 기존 1분 간격 제한·자동 수집 일정을 유지합니다.
- 취소 상태의 채팅 이력 복원, 분석 화면 자동 갱신, 서버 재시작 후 만료된 취소 요청 정리도 포함했습니다.
- 기존 데이터용 변경은 필드 추가 마이그레이션이며, 원천 데이터나 업무 정의를 변경하지 않습니다.

## 실제 화면·API 연계 검증

별도 임시 메타데이터 DB와 8001 검증 서버를 사용했습니다. 원천은 읽기 전용이며 AI 조건안은 고정된 로컬 검증 응답을 사용했습니다. 실제 외부 LLM은 호출하지 않았습니다.

1. 통합 화면의 실패 분석에서 재시도 → 새 분석 상세 → 원래 작업 연결 확인.
2. 원천 읽기 대기를 모의한 실행 중 취소 → 통합 화면에서 `취소 요청됨` 확인 → 대기 해제 후 `취소 완료`. 결과와 조회 시각은 저장되지 않음.
3. 프로젝트 대기 작업 취소 → 시작 시각이 없는 취소 기록 확인 → 재시도 → 같은 프로젝트·lot 범위를 유지한 완료 결과 확인.
4. 취소된 재시도 작업의 기존 질문 → 원래 답변·승인 초안 → 승인 → 원래 조건 복원 → 기준값 3/0.5와 승인 근거를 명시해 실행 → **37,251행 분석 완료**.
5. 채팅에서 미확정 조건안 생성 → 작업 상태에서 취소 → 조건 검토 버튼 비활성화 및 새 분석·질문 생성 없음 확인.
6. 실제 API로 원본/재시도 연결, 중복 재시도 미생성, 승인·답변 보존을 대조했습니다. 결과: `feature-bundle-4-qa.json`.

## 실제 앱 반영·보존

현재 로컬 앱 8000에 반영했습니다. 시작 스크립트의 초기 대기 시간이 초과됐지만 실제 서버 기동 완료 로그, 정상 상태 API, 관리 프로세스 재확인으로 실행을 확인했습니다. 상태 API의 메타데이터·원천 연결은 모두 정상입니다.

반영 전후 **프로젝트 3개, 공통 데이터셋 13개, 공통 카드 6개** 및 모든 프로젝트별 데이터셋·보드 정의의 해시가 동일합니다. 기록: `feature-bundle-4-live-before.json`, `feature-bundle-4-live-after.json`.

## 동작 한계

취소는 안전한 확인 지점에서 중단하는 방식입니다. 진행 중인 DB 조회·큰 정렬·AI 요청 자체를 즉시 강제 종료하지 않으며, 해당 호출의 종료 또는 제한 시간까지 `취소 요청됨`일 수 있습니다. 취소가 먼저 저장되면 늦은 결과는 반영하지 않습니다. 재시도는 원천을 다시 읽으므로 같은 조건이어도 결과가 달라질 수 있습니다. 지식 수집 취소는 자동 수집 예약을 끄지 않습니다.
