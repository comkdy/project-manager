# 두 번째 우선순위 묶음 구현 및 검증

검증일: 2026-10-23 (Asia/Seoul)

## 구현 결과

### 승인된 AI 지식과 SQL·데이터셋·카드 대화 연결

- 기존 지식 검색·승인·DB 매핑을 사용해 요청에 관련된 승인 정의를 SQL/카드 생성에 제공한다. 제안과 이전 대화에서 정의 이름, 업무 영역, 정의 버전, 매핑 버전을 확인할 수 있다.
- 같은 용어에 여러 업무 정의가 있으면 사용자가 선택한 뒤 생성을 계속한다. 후속 질문에서 이름을 다시 말하지 않아도 해당 대화의 선택 기준을 이어간다.
- 이전 대화의 근거는 서버 기록에서 복원한다. 오래된 대화가 최근 메시지 범위를 벗어나도 문맥을 유지한다.
- 미리보기·적용 시 승인 상태, 참조 정의, 매핑, 원천 구조, 사용자·DB·프로젝트 범위를 재검증한다. 적용 중 승인 철회와의 경합도 검사했다.
- 관련 정의의 필수 참조나 매핑이 사용할 수 없으면 생성을 중단한다. 단순히 일치하는 지식이 없는 일반 조회는 기존처럼 사용할 수 있다.
- 철회되거나 접근할 수 없는 근거에 의존한 과거 제안은 상세 SQL과 설명을 노출하지 않고 다시 작성하도록 안내한다.
- 화면은 ‘AI에 제공한 승인 지식’이라고 표시한다. 제공한 정의가 생성된 SQL에 정확히 반영됐다는 보증으로 표현하지 않는다.

### AI 분석의 실행 전 조건 확인·수정

- 분석 대화는 곧바로 계산하는 대신 조건안을 만든다. 이 단계에서는 분석 작업과 질문함 항목을 생성하지 않는다.
- ‘조건 확인·수정’으로 기존 PARA 분석 폼을 열어 기간, 대상, 반복 측정 처리, 표본 수, 변화량 기준을 확인하고 수정한다. 원래 사용자 요청 근거도 확인할 수 있다.
- 분석 종류·목적·프로젝트 범위는 조건안에 고정한다. 전체 통계·변화 탐지에 지정된 측정 구분·공정·PARA 범위도 유지한다.
- 일반 분석 입력과 각 조건안의 입력을 구분해 보존한다. 다른 화면을 왕복해도 수정값이 유지되며 숨겨진 폼은 반복 조회하지 않는다.
- 사용자가 확정한 뒤 기존 분석 작업·결과·질문·승인 흐름으로 연결한다. 확정한 조건은 후속 대화의 문맥에도 반영한다.
- 중복 확정은 같은 결과를 반환하고 작업을 추가 생성하지 않는다. 다른 조건으로 재확정하거나 오래된 버전을 제출하면 거부한다.
- 사용자 권한, 작업공간 버전, 프로젝트 범위, 원천 스냅샷을 실행 직전에 다시 검사한다. 느린 원천 목록 조회는 공통 실행 잠금 밖에서 처리한다.

## 브라우저 연계 검증

별도 검증 서버와 임시 메타데이터 DB에서 실행했다. 원천은 로컬 합성 데이터의 읽기 전용 연결이다. 모델 응답만 고정 검증 자료로 제공했고 지식 조회, SQL 검증·실행, 제안 저장, 승인, 분석 계산, 기록 복원은 실제 경로를 사용했다.

1. ‘검증지표’에 서로 다른 승인 정의 2개가 있을 때 SQL 생성 전 선택을 요청했다. 평균 정의를 선택한 후 정의 v1과 SQL 조회 결과 3행을 확인했다.
2. 제안을 기존 미리보기에서 검토하고 임시 공통 데이터셋으로 저장했다. 데이터 관리 목록의 공통 배지와 저장 완료 이력을 확인했다.
3. 용어를 반복하지 않는 ‘같은 기준으로 SQL을 다시 작성해줘’ 후속 질문에도 선택한 평균 정의 v1이 이어졌다. 저장된 대화를 재조회해 같은 출처와 대화 문맥을 확인했다.
4. 명시한 기간과 ‘모든 측정 포함’ 요청으로 분석 조건안을 만들었다. 실행 전 작업 수는 기존 검증 자료 1건 그대로였다.
5. 검토 폼에서 최소 표본 7, 평균 변화량 0.2로 수정했다. AI 지식 화면을 왕복해도 수정값이 유지됐다.
6. 확정 후 분석이 완료됐고 결과에 정확한 기간, 모든 측정 처리, 수정한 7/0.2 기준이 표시됐다. 새로고침 후 이전 대화에서 같은 결과를 다시 열었으며 중복 실행은 없었다.
7. 이전 묶음의 기존 분석에서 정확한 질문 → 해당 승인 초안 → 승인 → 원래 분석 조건 복원 경로를 다시 실행했다. 소수초를 포함한 기간과 반복 측정 기준이 유지됐다.
8. 승인 설명을 보고 3/0.5를 직접 입력하고 승인 지식 v1을 근거로 연결해 재분석했다. 실제 저장 요청을 대조해 원래 시각과 근거 버전 보존을 확인했다.
9. 공통 데이터셋의 `value` 열 삭제를 미리보기했다. 공통·프로젝트 보드 2개와 카드 4개, 그중 평균 카드 2개의 호환 문제가 표시됐다. 명시 확인 전 저장은 비활성화됐고 취소 후 버전은 v1 그대로였다.
10. 실제 앱을 최신 코드로 재시작했다. 기존 프로젝트 3개, 데이터셋 13개, 분석 카드 6개가 표시됐다. 검증 화면과 실제 앱의 브라우저 콘솔 오류·경고는 없었다.

최종 임시 분석 작업은 초기 검증 자료 1건 + 조건안 확정 1건 + 기존 승인 후 재분석 1건으로 총 3건이었다. 검증 서버를 종료하고 해당 임시 DB를 정리했다. 실제 앱은 `http://127.0.0.1:8000`에서 실행 중이다.

## 검증 범위

- 외부 LLM과 외부 SSO의 실시간 호출은 이번 화면 검증에 포함하지 않았다. 고정 모델 응답으로 상태·계약·기능 연결을 확인했고 모델의 업무 의미 이해 정확도를 검증한 것은 아니다.
- 데이터셋 영향 미리보기는 컬럼 구조와 카드 설정에 대한 검사다. 데이터 값의 의미나 Python 실행 결과까지 보장하지 않는다.
- 승인된 설명의 수치 조건을 자동 추정하거나 자동 실행하지 않는다. 사용자가 확인·입력·실행한다.
- 동시 처리의 권한·버전·잠금 경계는 테스트했지만 다중 사용자 전체 부하 벤치마크를 새로 수행하지는 않았다.
