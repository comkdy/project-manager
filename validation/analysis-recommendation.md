# 최초 분석 조건 추천 검증 — 2026-10-25

## 구현 범위

승인 사례와 대상 데이터셋을 선택하면 AI가 목표·비교 항목·표본 구분·측정 시점과 통계/ML 방법을 추천한다. 항목별 이유·승인 근거를 확인한 사용자가 한 번 실행하면 첫 계산과 이후 지속 분석을 함께 시작한다. 체크 해제로 단발 분석도 가능하다.

모호한 연결은 기존 확인 요청에 자연어 질문으로 등록한다. 답변→자동 정리→보완/검토·승인→원래 추천으로 돌아가기→승인 내용으로 추천 갱신을 지원한다. 추천 및 연결 질문은 기존 분석 기록/질문/지식 테이블에 저장하며 새 테이블을 추가하지 않았다.

변경 연결은 `KnowledgeWatchWorkspace/기존 채팅 분석 → EvaluationAnalysisPanel/EvaluationRecommendation → evaluation_recommendation → 기존 확인 요청/collector → execute/worker → KnowledgeWatch → 기존 결과 승인/채팅`이다. 기존 프로젝트·데이터셋·쿼리·카드 편집 저장 형식은 그대로다.

연결 설명을 일반 SQL/카드용 공통 정의로 사용하지 않도록 범위를 제한했다. 같은 사례 버전·데이터셋·프로젝트에서의 재사용과 정기 분석/재시도 자식 작업에 승인 근거가 유지되는 것을 검증한다. 첫 분석 실패→재시도→결과 검토 생성→지속 분석 재개도 검사했다.

## 실제 AI 연결 검증

`verify_analysis_recommendation_provider.py`로 현재 공용 AI 연결에 합성 사례와 가상 메타데이터만 전달했다. 실제 원천 측정값이나 사용자 지식은 전송하지 않았다. DB 쓰기도 없다.

1. alpha가 두 공정의 선폭 중 어느 것인지 불명확할 때 질문을 생성했다.
2. 승인된 설명에 해당하는 합성 근거를 추가하자 목표 `epm_1`, 설명 변수 `cd_a`/Recipe/장비, 표본 `lot_id`, 시간 `epm_at`으로 ML 추천을 생성했다. 제외해야 할 다른 공정 `cd_b`를 선택하지 않았다.
3. 모든 선택 컬럼과 인용을 서버 검증기에 통과시켰다.

근거: `analysis-recommendation-provider.json`, `analysis-recommendation-provider-response.json`. 두 번의 합성 입력 검증이며 실제 현장의 다양한 표현에 대한 정확도 평가를 대신하지 않는다.

## 브라우저 검증

임시 관리 DB와 합성 원천 데이터를 사용했다. 이 시험 앱의 자연어 정리/추천 응답은 고정 응답이며, UI·SQL 조회·ML 계산·승인·검색은 실제 앱 경로다. 실제 AI 판단은 위의 별도 시험으로 확인했다.

1. 자연어 평가 사례 등록→기존 확인 요청에서 승인.
2. 승인 사례+대응 데이터셋 선택→AI 추천 준비→모호한 연결 질문 자동 등록.
3. 확인 요청에서 목표/선행 항목/같은 wafer/Lot/결과 시각을 자연어로 답변→간결한 연결 설명 검토→승인.
4. ‘분석 추천으로 돌아가기’→추천 자동 갱신. 목표·비교 항목·Lot·시간을 직접 선택하지 않고 표시된 추천 확인.
5. ‘이 추천으로 분석 시작’ 한 번→첫 ML 실행과 지속 분석 등록. 실제 488행 조회, 학습 383행/이후 검증 98행/같은 Lot 경계 7행 제외. MAE 0.6998929, 중앙값 기준 5.448016, R² 0.9793451.
6. 완료 결과가 확인 요청에 자동 등록→승인→기존 AI 채팅에서 `epm_b` 관련 승인 계산 결과와 추가 분석 제안을 검색.

이 수치는 합성 데이터의 두 EPM 계열을 이용한 연결 시험으로 실제 공정의 원인 효과를 검증한 결과가 아니다. 화면: `.local/analysis-recommendation-ready.png`. 자동 검토 생성 후 결과 화면의 상태 갱신도 연결했고, 이미 시작한 지속 분석의 중복 시작 입력을 숨겼다.

## 실제 앱과 데이터 보존

관리 앱을 재시작해 새 서버/화면을 반영했다. 정상 응답, 배포 묶음 일치, 새 추천 목록 API를 확인했다. `verify_evaluation_preservation.py after analysis-recommendation` 결과 **31개 테이블·1,226행 전체 내용 지문이 동일**하다. 근거는 `analysis-recommendation-metadata-before.json`, `analysis-recommendation-metadata-after.json`이다.

시험 서버를 종료하고 해당 임시 관리 DB 정리를 확인했다. 실제 앱에는 시험 승인·추천·자동 분석을 생성하지 않았다. 초기 사용은 승인 사례와 대상 데이터셋 선택부터 시작한다. 데이터셋 자체의 새 조인/피벗 작성은 기존 데이터셋/채팅 기능을 사용하며, 추천이 불명확한 연결을 대신 확정하지 않는다. 원시 행을 모델에 보내지 않으며 실행 결과의 지식 승인은 계속 사람의 검토를 요구한다.
