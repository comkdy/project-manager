# 평가 사례 기반 데이터셋 추천 검증

2026-10-25. 실제 앱 `http://127.0.0.1:8000/`에 반영.

## 사용 흐름

AI 지식 → 평가 사례 → 지식을 바탕으로 새 데이터 지속 분석 → 승인 사례로 분석 준비.

1. 승인 사례와 분석 범위를 선택한다. 공통 사례는 분석할 프로젝트 또는 공통 데이터를 선택할 수 있다.
2. AI는 현재 범위의 데이터셋 정의·출력 컬럼과 승인 지식을 확인한다. 원시 행 전체를 모델에 전달하지 않는다.
3. 적절한 기존 데이터셋을 추천한다. 없으면 기존 SQL·피벗 작성 규칙과 검증 도구로 데이터셋 생성안을 준비한다.
4. 모호한 표본 대응·항목·시점은 확인 요청에서 자연어로 설명하고 검토·승인한다. 같은 화면의 복귀 버튼으로 추천을 이어간다.
5. 생성안은 기존 데이터셋 제안 편집·미리보기·적용 기능을 사용한다. 사용자가 적용하기 전에는 데이터셋을 저장하지 않는다.
6. 선택·생성한 데이터셋과 승인 설명으로 첫 분석 조건을 추천한다. 확인 후 기존 통계·ML 작업, 결과 검토·승인, 지식 축적 흐름으로 이어진다.

데이터셋을 직접 선택하는 기존 방법도 접어 둔 선택 항목으로 유지했다. 프로젝트·데이터 관리·쿼리·카드 편집·채팅의 기존 진입점과 기능을 유지했다.

## 지속 분석의 계산 방식

기존에도 매시간 ML을 반복하지 않았다. 주기적으로 선택 범위의 데이터 지문을 비교하고, 변경이 발견된 경우에만 분석 작업을 만든다. 화면의 표현을 **변경 확인 주기**로 명확히 했다.

- 같은 데이터: 기존 결과 유지, 새 계산·검토 요청 없음.
- 추가·수정·삭제된 데이터: 확인된 분석 조건으로 다시 계산하고 결과를 확인 요청에 전달.
- 감지는 주기 조회 방식이다. 외부 DB에서 앱에 변경 이벤트를 보내는 기능은 추가하지 않았다.
- 변경 시 선택 범위 전체를 다시 분석한다. 새 행만 추가 학습하는 증분 ML은 아니다. 변경 확인 조회 자체의 비용도 남는다.
- 승인 지식·데이터 정의·권한·범위가 달라지면 실행을 막고 재확인한다. 완료된 결과는 같은 DB로 돌아왔을 때 계속 확인할 수 있다.

## 확인 결과

- 서버 전체 회귀 검사: **1,282개 통과**. 최종 보완 후 관련 검사 **86개 통과**.
- 화면 로직 검사: **224개 통과**, TypeScript·배포 빌드·채팅 기능 계약 검사 통과.
- 실제 연결 AI + 합성 메타데이터: 모호한 연결 질문 → 승인 설명으로 기존 데이터셋 추천 → 데이터셋이 없는 경우 생성안 제안, 3단계 통과.
- AI가 질문과 잠정 추천을 동시에 내면 질문만 채택한다. 검증되지 않은 선택·SQL은 사용하지 않는다. 응답 형식·인용 검증 실패는 1회만 자동 재시도하며 미검증 결과를 적용하지 않는다.
- 분리된 검증 앱의 실제 화면: 자연어 사례 등록·승인, 데이터 연결 질문·답변·승인·복귀, 생성안 이름 수정·미리보기·적용, 재질문 없는 분석 추천, **488행 ML 계산**, 결과 승인·지식 반영 확인.
- 같은 데이터의 즉시 변경 확인 후 `데이터 변경 없음 · 기존 분석 결과를 유지합니다.` 표시. 분석 작업 수 1개 유지.
- 기존 채팅에서 데이터셋 작성 제안과 카드 구성 제안 확인.
- 실제 앱의 기존 **31개 테이블, 1,226행 내용 동일**. 추천 상태 보존용 빈 테이블 1개만 추가했다. 실제 앱에는 검증용 승인·데이터셋·지속 분석을 만들지 않았다.
- 검증용 서버와 임시 DB는 정리하고 실제 앱은 실행 상태로 유지했다.
