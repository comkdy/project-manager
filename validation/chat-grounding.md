## 문제와 수정

실제 질문은 “XXXA에서 operA 에 따른 특성 변화가 관측돼?”였습니다. 기존 조건안에서는 프로젝트 이름 XXXA를 Inline 측정 항목으로, operA를 확인되지 않은 공정으로 넣고 시간 추세/원인 요청으로 해석했습니다. 분류 단계에 실제 프로젝트·공정·측정 항목 목록이 없었고, 후속 검증이 잘못된 대상을 사용자 입력 문제로 넘겼습니다.

등록된 이름을 분류 단계에 제공하고, 서버에서 프로젝트/공정/PARA를 검증합니다. operA와 oper A처럼 공백·대소문자만 다른 이름은 실제 목록의 유일한 항목에 연결합니다. oper1 같은 별개 이름은 임의 대응하지 않습니다. 잘못된 프로젝트/PARA 연결은 제한된 재해석을 거치며, 모호한 이름은 질문합니다.

실제 모델 검증에서는 “관측돼?”를 과거 사례 조회로 보내는 추가 문제를 발견했습니다. 현재 관측 질문도 계산 요청임을 분류 지침의 최종 작업 설명에 명시하고 과거 사례 설명과 구분했습니다. 프로젝트·공정 예시는 동일 문장을 강제로 분기하는 코드가 아니라 모델의 분류 지침에 포함했습니다.

전체 프로젝트 채팅에서 명시한 XXXA 범위는 조건안에 보존됩니다. 대화의 원래 범위와 분석 대상 범위를 분리해 저장·복원하고, 조건 검토 화면에서도 실제 대상 프로젝트를 사용합니다. 조건안을 저장하기 직전 최신 등록 목록을 다시 검증합니다.

## 원래 질문에 대한 별도 탐색 계산

현재 합성 DB에서 XXXA의 oper A Recipe별 후속 특성을 읽기 전용으로 계산했습니다. 화면의 2026 WW40 이후를 탐색 범위로 삼았습니다(2026-09-28 00:00 KST 이후). 이 기간은 이번 별도 탐색의 가정이며 앱 분석안에 사용자 조건으로 자동 기록하지 않았습니다.

측정 이전 마지막 oper A 이력을 대응시키고, 위치별 마지막 측정(마지막 NULL 유지, 동률은 record_id)을 wafer 평균으로 집계했습니다. 642 wafer-측정 항목 행을 모두 조회해 계산했습니다. 재방문/Recipe 혼합/이력 미대응은 없었고 마지막 NULL 위치 48개는 평균에서 제외했습니다.

| 항목 | RCP1 평균 | RCP2 평균 | RCP3 평균 | 표본 |
|---|---:|---:|---:|---|
| Inline oper A CD MAIN | 30.00146 | 30.24192 | 30.25283 | 54 wafer / 4 Lot |
| EPM PARA1 | 0.722600 | 0.722714 | 0.723582 | 96 wafer / 8 Lot |

같은 Lot 내 차이를 비교한 선형 모형에서도 Inline MAIN의 RCP2−RCP1은 +0.21299, RCP3−RCP1은 +0.22201이었습니다. EPM PARA1의 같은 비교는 −0.000377, +0.000160으로 방향이 일정하지 않았습니다. 다른 Inline SUB1/SUB2도 비슷한 방향이었고, EPM PARA2~PARA5는 이번 Lot 조건을 고려한 비교에서 Recipe 구분에 따른 차이가 상대적으로 작았습니다.

Inline의 Recipe별 차이는 관측되지만 인과 효과·규격 위반·통계적 유의성을 판정한 것은 아닙니다. Inline과 EPM은 해당 기간에 측정된 wafer/Lot 구성이 달라, 이 결과만으로 Inline 변화가 EPM으로 전달됐는지 판단할 수 없습니다. 같은 wafer와 기간을 맞춘 재검증이 필요합니다. 이 합성 데이터 결과를 사내 실험 결과로 사용할 수 없습니다.

원본 추출 및 조건은 `oper-a-question-data.json`, 계산 결과는 `oper-a-question-result.json`에 있습니다. 이번 탐색은 별도 로컬 검증이며 앱의 승인된 지식으로 등록하지 않았습니다. 앱의 분석 조건 확인·질문·승인 절차는 유지합니다. 앱이 모든 미정 조건을 자동 결정하고 분석까지 완료하도록 변경한 작업은 아닙니다.

## 평가 사례 두 건의 의미와 삭제 판단

평가 사례는 원본 측정값을 저장하는 화면이 아니라, 관측 내용·적용 범위·연결된 데이터 항목·조건·근거·검토 기록을 묶은 지식입니다. 자연어를 남기고 관련 항목을 구조화하며, 실제 데이터에서 실행한 결과는 분석 이력/데이터셋 버전과 연결됩니다. 원본 측정값은 연결된 원천 DB에 있고 데이터셋은 그 조회 정의입니다.

1. `ceb1f7d8-1f3c-4bb7-96dd-7bd9bf46e230`: “XXXA oper B Recipe별 Inline MAIN·EPM PARA3 관계”. 2026-10-25 생성한 자연어 관측 시연 사례, 승인 v1.
2. `b7439730-d434-4f34-9480-63b7601ad4a9`: “현재 데이터 분석: XXXA oper B Recipe별 Inline MAIN·EPM PARA3 wafer 단위 결합 · 242797fb”. 같은 날 실제 계산 후 승인한 시연 결과, 승인 v1. 분석 실행 `242797fb-7de0-4641-a92f-ad78c3339a28`에 연결됩니다.

둘 다 현행 시스템의 합성 데이터 시연 기록이며 구형 시스템의 잔여 데이터가 아닙니다. 따라서 “시스템 개선 전 데이터라면 삭제” 조건에 해당하지 않아 유지했습니다. 둘은 확정된 인과 법칙이나 실제 사내 평가 사실을 의미하지 않습니다.
