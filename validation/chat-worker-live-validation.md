# 실제 OpenRouter → 통계·ML → 확인 요청 검증

후속 상태: 사용자의 추가 승인 요청에 따라 이 문서의 ML 검토 대기 한 건은 지식으로 승인됐다. [승인 및 실제 챗 활용 검증](chat-worker-approved-knowledge.md)에 최신 상태를 기록했다. 아래 내용은 승인 전 검증 시점의 기록이다.

2026-10-25, 현재 설정 `openrouter.ai` / `z-ai/glm-5.3-flash`를 사용했다. 사용자가 승인한 검증 질문·XXXA 데이터셋 SQL/출력 컬럼·관련 승인 지식만 전달했다. 원시 측정 행은 전송하지 않았다. 현재 DB는 합성 공정 데이터이므로 아래 수치를 실제 사내 공정 효과로 해석하지 않는다.

## 발견한 문제와 수정

1. 실제 모델이 상관 분석에 하나의 목표와 ML 설명 변수·Lot·시각 설정을 섞었다. 방법별 설정 스키마를 분리해 상관은 두 수치, 그룹 비교는 그룹과 수치, ML은 목표·설명 항목·Lot·시각으로 제한했다. 잘못된 계획을 자동 변환하지 않고 검증 및 한 번의 모델 수정을 거친다.
2. 근거 인용에 떨어진 SQL 구절을 `...`로 이어 붙이는 응답이 나왔다. 짧은 연속 원문을 인용하도록 지침과 예시를 보강했다. 기존 원문 일치 검증을 유지했고 실패한 계획은 실행하지 않았다.
3. 미확인 장비 상태를 Recipe/Inline으로 대체 제안하는 질문이 나왔다. 질문 단계에는 확정되지 않은 계산 설정·컬럼 연결 근거를 함께 붙일 수 없도록 분리했다. 질문 형식을 명시하고 검증 실패 진단 로그도 추가했다. 최종 장비 상태 질문은 계산 없이 확인 요청으로 연결됐다.
4. 계획 호출에는 `data_analysis_context`만 넣고, 다른 경로의 카탈로그나 조회 결과가 섞이지 않도록 제한했다. 원시 행을 넣은 가짜 기존 컨텍스트가 모델 요청에 전달되지 않는 회귀 검사도 추가했다.

첫 상관 요청과 중간 모호성 재검증 한 번은 형식/근거 검증에서 거절됐다. 해당 호출에서는 분석이 시작되지 않았다. 최초 거절된 상관 응답은 `chat-worker-plan-diagnostic-before-fix.json`, 수정 후 실모델 요청·응답은 `chat-worker-plan-diagnostic.json`에 보존했다. 최종 결과 파일을 최초부터 전부 성공했던 기록으로 해석하지 않는다.

|---|---|---|

| 지정된 목표/설명 변수 ML | 동일 로컬 워커의 시간·Lot 분리 검증, 설명·확인 요청 연결 | `4591b8bf-fb52-45a0-8626-0e1fd4bd176f` |
| 일반 용어로 Recipe·Inline 중 EPM 예측에 중요한 항목 질문 | 데이터셋을 선택하지 않아도 XXXA 결합 데이터셋 v2 선택, 승인 사례의 Lot 검증 근거 인용 후 ML 실행 | `d5ca59f2-f0df-4d35-97ad-17b35236b578` |
| 데이터/컬럼이 미정인 ‘장비 상태’ ML | 계산하지 않고 자연어 확인 질문 생성, 결과·지식 없음 | `ec547841-e3fe-481c-8a1a-c979d98a30b1` |

ML: 243행 중 과거 학습 183행, 미래 검증 49행, 검증 Lot과 겹친 11행 학습 제외. MAE 0.00546758, 중앙값 기준 0.04171224, R² 0.9762747. 예측 기여 후보 `inline_main`, `recipe_b`. 인과 효과나 영향 비율로 표현하지 않는다. 실제 수치는 로컬 워커가 계산하며, 현재 챗의 결과 설명은 그 수치와 검증 상태에 근거한 서버 문장이다.

선택 없이 질문한 문장: “XXXA에서 oper B의 Recipe와 Inline MAIN을 함께 고려하면 EPM PARA3 예측에 어떤 항목이 중요해? 관련 데이터셋과 승인된 평가 사례를 찾아 현재 데이터로 ML 분석하고 다음에 확인할 점도 알려줘. 별도 기간이나 필터는 지정하지 않을게.”

이 질문은 승인 사례 `ceb1f7d8-1f3c-4bb7-96dd-7bd9bf46e230`의 “같은 lot_id를 양쪽에 나누지 않습니다”를 인용했다. 진단 요청에는 승인 평가 사례 2개가 포함됐다. 별도 승인 용어 정의는 검색되지 않아 0개였으며, ‘승인 지식 전체가 없음’을 뜻하지 않는다.

## 검증 명령과 증거

- `verify_chat_worker_live.py correlation`, `group_compare`, `ml_regression`, `natural_ml`, 최종 `ambiguous`: 모두 exit 0. 각 응답/복원 증거는 `chat-worker-<유형>-live.json`.
- `verify_chat_worker_live_final.py`: exit 0. 실제 진단 요청의 계획 컨텍스트/사실 JSON에 원시 행·미리보기·조회 결과가 없음을 확인. 승인 사례 인용·미승인 초안·질문만 존재하는 대기 상태 검사. 요약 `chat-worker-live-final.json`.
- 기존 분석·데이터셋·카드·채팅·프로젝트 경계·승인 전파 회귀: `chat-worker-analysis.md`의 전체 백엔드 명령으로 **314 passed**, exit 0 (90.31초).
- 마지막 질문 계약·진단 변경 후: `python -m pytest backend/tests/test_chat_data_analysis.py backend/tests/test_evaluation_recommendation.py backend/tests/test_chat_history.py backend/tests/test_chat_workflow.py -q`: **59 passed**, exit 0 (17.91초). 위 검사와 중복되므로 합산하지 않는다.
- `verify_dataset_boundaries_live.py`: exit 0. XXXA/XXXB/XXXC/공통 목록 분리, 원천 범위 우회 차단, 기존 XXXA 카드 **7개 모두 정상 조회**.
- `verify_chat_worker_preservation.py`: exit 0. 기존 **32개 테이블 1,551행** 해시 동일. 데이터셋·대시보드·승인 지식·기존 대화 보존. 추가 기록은 검증 실행/대화/질문/검토 초안/감사 및 조회 컨텍스트.
- 이전 구현 단계의 화면 전체 **231 tests**, TypeScript/Vite 빌드 성공 기록은 유지한다. 이번 후속 수정은 백엔드 계획/검증에 한정되므로 화면 코드는 수정하지 않았다.

자동 검증은 각각의 지정 시나리오와 회귀 범위에 대한 결과다. 외부 모델의 모든 자유 질문이 항상 올바르게 해석된다는 보장은 아니다. 서버는 근거·범위·설정 검증 실패 시 계산을 진행하지 않는다.
