# 세 번째 우선순위 묶음 구현·검증 결과

검증일: 2026-10-23 (Asia/Seoul). 최종 빌드를 로컬 앱 `http://127.0.0.1:8000`에 적용했습니다.

## 구현한 범위

1. 편집 내용 자동 보관과 명시적 비교·복구: SQL/간편 쿼리, 일반/Python/간트 카드, 지식 정의·매핑, 질문·답변, 승인 초안·검토 사유.
2. 서버 충돌 비교: 보관 당시 기준 버전을 유지하고 최신 내용과 비교한 뒤 재검토·저장. 다른 카드의 변경과 배치를 유지합니다.
3. 통합 작업 상태: 분석, 현재 사용자의 미확정 AI 조건안, 관리자 지식 수집 기록과 기존 결과·질문·조건 검토 연결.
4. 데이터 시각 구분: 상태 확인·원천 조회·분석 범위 마지막 측정·카드 조회·간트 기준 시각을 구분하고 없는 시각은 추정하지 않습니다.

사용 범위와 제한: [편집 복구와 작업 상태](../EDIT_RECOVERY_AND_ACTIVITY.md).

## 실제 화면 연계 검증

별도의 임시 메타데이터 서버(8001), 읽기 전용 원천 연결, 고정된 로컬 모델 응답을 사용했습니다. 실제 앱의 업무 정의는 수정하지 않았습니다.

- **SQL**: 미저장 SQL 입력 → 즉시 새로고침 → 비교·복구 → 다른 편집자의 v2 저장과 충돌 → 최신 내용 비교 → 내 내용 유지 → SQL 실행·기존 변경 영향 검토 → v3 저장. 공통 및 프로젝트 보드 4개 연결 카드의 영향 표시와 공통 카드의 실제 v3 조회를 확인했습니다.
- **카드**: 제목 수정 → 새로고침 → 비교·복구 → 다른 카드가 동시에 수정된 보드와 충돌 → 비교 후 저장. 복구한 제목과 다른 편집자의 별도 카드 제목을 모두 보존했습니다.
- **Python 카드**: 간편 편집에서 Python 전환 → 스크립트 수정 → 닫기·재열기 → 모드와 스크립트 복구 → 기존 실행 경로에서 정상 차트 표시. 실행 중 입력·복구 버튼 잠금도 확인했습니다. 서버에는 테스트 코드를 저장하지 않았습니다.
- **지식**: 설명·변경 사유 입력 → 상세 닫기·재열기 → 비교·복구 → 다른 편집자의 v2와 충돌 → 비교 후 v3 초안 저장. 기존 승인 v1 제공 상태를 유지했습니다.
- **승인 흐름**: 검토 사유 입력 → 새로고침 → 복구. 작업 상태에서 기존 분석 → 정확한 질문 → 해당 승인 초안 → 복구된 사유로 승인 → 원래 분석 조건 복원 → 기준 3/0.5와 승인 지식 버전 연결 → 분석 완료.
- **AI 조건안**: 채팅에서 미확정 조건안 생성 → 작업 상태에 ‘실행 전 확인’ 표시 → 조건 확인·수정 → 기준값 입력 → 명시적 실행 → 완료 작업 표시. 미확정 조건안은 사라지고 실행은 한 건만 추가됐습니다.
- **조회 시각**: 카드 캐시의 실제 데이터셋 버전과 조회 시각, 분석 대상 범위의 마지막 측정, 미실행·실패 작업의 기록 없음 표시를 확인했습니다. 실제 앱에서는 기존 간트의 기준 시각도 확인했습니다.
- **최종 콘솔**: 실제 앱과 검증 앱에서 경고·오류 로그 없음.

최종 API 교차 확인은 [feature-bundle-3-api-checks.json](feature-bundle-3-api-checks.json)에 기록했습니다. 데이터셋 v3, 보드 v3, 지식 초안 v3, 총 분석 4건 중 완료 3건과 테스트 실패 1건, 질문 반영 및 승인 초안을 확인했습니다. 해당 프로젝트에 공통 작업이 섞이지 않는 것도 확인했습니다.

## 교차 검토 중 수정한 경계

- 미확인 보관 초안을 서버 저장 과정에서 지우지 못하도록 차단.
- 저장 대기 중 입력·복구·모드 변경을 잠가 성공 응답 뒤 새 입력이 사라지는 문제 방지.
- 새 카드 복구 시 실제 복구 카드 ID로 최신 충돌 내용을 조회.
- 손상된 필터·피벗·카드 옵션 등의 중첩 구조 검사.
- 간트의 원래 데이터셋이 사라지거나 필수 컬럼이 바뀌면 자동으로 다른 데이터셋을 선택하지 않고 재선택 안내.
- 간트의 후속 페이지 조회 실패가 과거 성공 결과에 가려지지 않도록 최근 오류 시각까지 비교.
- 비교 화면의 입력 항목 한글화, 내부 상태 필드 제외, 바뀐 항목 강조.

## 실제 작업공간 보존과 정리

적용 전후 프로젝트 목록, 각 범위 데이터셋, 공통·프로젝트 보드 전체 정의의 해시가 동일합니다. 프로젝트 **3개**, 공통 데이터셋 **13개**, 공통 카드 **6개**를 보존했습니다. [적용 전](feature-bundle-3-live-before.json), [적용 후](feature-bundle-3-live-after.json).

로컬 앱을 정상 재시작했고 `/api/health`의 메타데이터·원천 연결이 모두 정상입니다. 새 작업 상태 화면에서 기존 작업 20건을 읽었습니다. 임시 검증 서버와 생성한 임시 메타데이터 DB는 제거했습니다. 원본 파일 백업은 `.local/feature-bundle-3-baseline-2026-10-23.zip`입니다.

## 확인 범위의 한계

복구는 현재 브라우저 저장소를 사용하며 기기 간 동기화나 서버 백업은 아닙니다. 실제 외부 LLM·사내 SSO 공급자와의 연결 시험은 이번 검증에 포함하지 않았습니다. 작업 상태는 저장된 실행 기록의 제한된 목록이며 원천 전체의 최신성을 실시간 감시하지 않습니다. 재시도·취소는 후속 범위로 남겼습니다.
