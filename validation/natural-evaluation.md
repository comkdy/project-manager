# 자연어 평가 사례·용어 연결 검증 — 2026-10-25

## 변경 범위

평가 사례를 적용 범위와 자연어로 등록하고, 승인 지식으로 용어를 연결한다. 복수 해석·미연결 용어는 같은 확인 요청에서 묻고 자연어 답변으로 보완한다. 검토 화면은 AI의 해석과 확인할 내용 중심으로 정리했으며 상세 근거·원문·선택적 검토 메모는 접었다. 기존 프로젝트·데이터셋·쿼리·카드 편집·일반 채팅 기능은 유지한다.

연결 경로는 `등록 → 기존 질문/답변 → 원문 근거 추출 → 승인 용어·연결 재확인 → 짧은 확인 질문 → 자연어 보완 → 기존 승인 → 사례 검색/채팅 → 기존 분석 실행/결과 검토`다. 새 DB 테이블이나 기존 데이터 변환은 없다. 예전 dataset 기반 사례와 새 case_context 사례를 구분해 호환한다.

## 새 회귀 시나리오

- 데이터셋 없는 공통/프로젝트 등록, 원문 보존, 중복 요청 재사용, 삭제된 프로젝트 차단.
- 유효한 승인 지식 연결, 폐기된 데이터 연결·지식 버전 변경 재확인, 다른 프로젝트의 별칭 혼용 차단.
- 모호한 용어 질문→자연어 답변→같은 요청에서 승인. 사용자가 모른다고 한 용어는 반복 질문 억제.
- 답변 인용·지식 ID 조작 차단, 해석 응답이 불완전할 때 원문을 유지하고 처리 실패 표시.
- 최신 답변보다 오래된 초안 승인 차단. 보완 요청의 검토 메모와 기존 질문을 후속 해석에 전달.
- 새 범위 기반 사례→기존 분석 작업자→결과 검토→승인→사례 검색. 계산 수치·실행 근거의 기존 위조 방지 유지.

## 브라우저에서 확인한 흐름

별도 시험 DB와 고정 AI 응답으로 `http://127.0.0.1:8001/`에서 다음을 실제 조작했다.

1. 공통 범위와 자연어만으로 사례 등록.
2. alpha의 의미를 묻는 추가 설명 요청 확인.
3. 자연어 설명 입력 후 같은 요청이 승인 필요 상태로 바뀜.
4. 보완 요청→추가 답변→같은 요청 승인→반영 완료.
5. 기존 AI 채팅에서 승인된 사례 검색. 데이터셋 없는 사례가 공통 사례로 표시됨.
6. 비교 데이터셋 요청 제안으로 기존 채팅 입력이 채워지고, 전송 후 기존 SQL 제안·조회 미리보기에서 실제 3행 응답 확인. 생성은 적용하지 않음.

이 과정에서 보완 요청 메모가 답변자에게 보이지 않는 문제를 발견해 화면·응답을 수정했고, 최종 서버 검사로 검토 메모와 후속 해석 전달을 확인했다. 고정 응답은 기능 연결 확인용이며 분석 SQL의 과학적 타당성을 검증하는 용도가 아니다. 새 사례의 분석 실행·결과 승인 경로는 위 서버 통합 검사로 검증했다.

배포 후 실제 앱에서 등록 입력이 범위+자연어인 것과 기존 평가 사례의 간결한 검토 화면을 확인했다. 실제 사례를 새로 등록하거나 승인하지 않았다. 화면 자료: `../.local/natural-evaluation-registration.png`, `../.local/natural-evaluation-live-review.png`.

기존 `verify_evaluation_ui.cjs` 같은 외부 브라우저 자동화 스크립트는 이번 검사에 사용하지 않았다. 이번 브라우저 검증은 Codex 브라우저 제어로 수행했다.

## 한계와 후속 방향

- 실제 AI 응답 검사는 합성 사례 1건의 두 차례 대화다. 실제 제조 사례 전체의 정확도·분석 추천 품질을 보증하지 않는다.
- 기존 승인 정의에 연결된 별칭은 후속 사례에서 재사용한다. 승인 정의가 없는 사용자 설명은 보관하지만 실제 컬럼·값 연결이 완료된 것으로 간주하지 않는다.
- 모호한 질문을 모두 채울 수 없어도 원래 관측을 보관할 수 있다. 지식 승인과 물리 데이터 연결, 인과관계 확정은 서로 다른 상태다.
- 현재 수치 분석은 그룹 통계와 Pearson 상관관계다. AI가 지속 유입 데이터를 보고 분석 질문을 선택하는 흐름, ML 작업자, 조건별 관계의 누적 설명은 후속 구현이다. [설계 방향](../design/KNOWLEDGE_CASE_FLOW.md)에 현재 상태와 분리해 기록했다.
