# 지식 기반 지속 분석 검증 — 2026-10-25

## 구현과 변경 영향

승인 사례와 기존 데이터셋으로 한 번 분석 조건을 정하고, 새 데이터가 생기거나 기존 데이터가 바뀌면 통계/ML 계산을 반복한다. 결과는 확인 요청에서 검토·승인한 뒤 AI 지식과 기존 채팅의 사례 검색에 재사용한다.

주요 연결: `SemanticWorkspace → KnowledgeWatchWorkspace → EvaluationAnalysisPanel → evaluation_analysis → 기존 분석 작업자 → evaluation_compute/evaluation_ml → knowledge_watch → evaluation_results → 기존 확인 요청·승인 → 사례 검색/채팅`. 정기 확인은 기존 분석 일정 작업자를 재사용한다.

- 새 저장 구조는 `app_knowledge_watches` 하나다. 기존 프로젝트·데이터셋·쿼리·카드 편집의 구현 및 저장 형식을 변경하지 않았다.
- 기존 결과에 데이터 내용 지문과 선택적인 ML 결과가 추가된다. 기존 통계 방법 및 기존 저장 채팅의 복원 경로를 유지한다.
- 최초 대상 선택은 사용자 확인이 필요하다. 스스로 모든 PARA를 연결하거나 새 조인/원인 가설을 만들어 무제한 분석하는 기능은 아니다.
- 범위/역할/버전 충돌, 중복 일정 실행, 재시도·취소, 승인 수치 위조, 대기열 한도를 기존 제약과 함께 검사한다.

## 브라우저 연결 검증

별도 임시 관리 DB와 기존 합성 원천을 읽기 전용으로 사용했다. 자연어 정리/의도 라우팅은 고정된 시험 응답이며 SQL 조회·ML 계산·승인·사례 검색은 실제 앱 경로를 실행했다.

1. 범위+자연어 사례 등록 → 확인 요청 → 승인.
2. 승인 사례를 명시적으로 선택 → 대응된 평가 데이터셋 선택 → ML 실행.
3. 실제 조회 488행, 유효 488행. 학습 383행, 이후 검증 98행, 같은 Lot이 경계에 걸친 7행은 학습에서 제외.
4. ML MAE 0.6998929, 중앙값 기준 MAE 5.448016, R² 0.9793451. `epm_a → epm_b`의 합성 데이터 실험이며 실제 공정 인과관계 검증 결과가 아니다.
5. 결과 화면에서 지속 분석 시작 → 확인 요청 자동 생성 → 지금 확인 시 변경 없음 → 일시정지·재개.
6. 자동 생성된 계산 결과 승인 → 지식 목록 반영 → 기존 AI 채팅에서 `epm_b` 관련 승인 결과 검색 및 추가 분석 제안 확인.

화면 기록: `.local/knowledge-watch-ml.png`, `.local/knowledge-watch-chat.png`, `.local/knowledge-watch-live.png`. 검증 중 다른 확인 요청을 열어도 이전 승인 안내가 남는 문제를 수정했다. 임시 서버 종료 및 해당 임시 DB 정리를 확인했다. 실제 앱에 시험 사례·승인·지속 분석을 만들지 않았다.

## 운영 범위와 한계

서버가 켜져 있고 대상 DB가 선택되어 있을 때 기본 1시간 간격으로 확인한다. 선택 범위 전체의 지문 확인 후 변경된 경우 재계산한다. 실시간 수집/CDC, 증분 모델 학습, 원천 데이터 쓰기, 인과 효과 추정은 포함하지 않는다. 최초 데이터 대응과 분석 항목을 확인해야 하며 미확인 연결을 임의로 채우지 않는다. 새 결과는 자동 승인하지 않는다.

수십 명 규모의 기존 앱 작업자와 DB를 사용한다. 지속 분석 최대 30개, 내용 확인 최대 200,000행, ML 최대 20,000행·8개 설명 항목의 한도를 둔다. 대규모 생산 데이터에서의 처리량·장기 성능과 실제 평가 사례의 해석 정확도를 입증한 시험은 아니다. 자세한 사용법과 제한은 `EVALUATION_CASES.md` 참조.
